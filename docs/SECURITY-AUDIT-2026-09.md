## 4. Spotify-режим і BPM — аналіз

Архітектура (перевірена по коду, файл-шлях перевірений живцем):

```
джерело → визначення темпу → сітка биту → споживачі
Spotify embed ──(playback_update pos/paused)──▶ beatEngine base='track'
   + Deezer BPM (oEmbed→JSONP) ─ setGrid(bpm, phase 0) ─ «tap once to align»
Local file ── decode ─▶ histogram ∥ essentia RhythmExtractor2013 (worker) ─▶ setGrid(bpm, offset)  ← найточніший шлях
Tab/Mic capture ─▶ micEq FFT ─▶ liveBpm (histogram scout, instant lock)
                 └─▶ PCM ring ─▶ liveEssentia кожні 6/12 с ─▶ mergeTempo(TempoCNN) ─▶ setGrid ─▶ beatPll (phase glue)
                                                          + userOffset ±300 мс (Bluetooth-латентність)
beatEngine.onBeat ─▶ пульс дошки, BeatCombo, VictoryScene-строби; beatMode.snapPlan ─▶ хід приземляється на біт
```

Висновки:

- Розподіл ролей грамотний: histogram = миттєвий скаут, essentia = суддя
  темпу+фази, TempoCNN = арбітр октавних помилок, PLL = безперервна фаза,
  offset = вуха користувача. Flywheel/silence-gate закривають брейкдауни.
- **Обмеження Spotify, які не обійти без OAuth:** embed без логіну грає
  30-секундні прев'ю (сітка скидається щоразу), точний `audio-analysis`
  API закритий для нових застосунків (2024). Тому «ідеальний» режим — це
  локальний файл або Tab audio. Додано підказку під плеєром.
- Deezer-BPM буває вдвічі більший/менший або відсутній — існуючий
  сanity-діапазон 40..220 + live-детекція + тап це покривають; змінювати
  не треба.
- Виправлено в V1: зависання плеєра (C5), ключ BPM-пам'яті (C6), санітизація
  плейлистів (S7). Перевірено в проді під CSP: embed вантажиться, Deezer
  віддає 113.3 BPM для тестового треку, ключ у сховищі — URI.
- Не міняв навмисно: пороги впевненості (0.25 файл / 0.35 live), кадансу
  essentia, коефіцієнти PLL — усі підібрані на ~150 треках у липні; без
  нового корпусу треків правити їх наосліп шкідливо.

## 5. Що перевірити після деплою rules (ручний чек-лист)

1. Соло-гра Strong до кінця → запис у `/games`, `bestGamePoints` оновився.
2. Соло-гра Casual → запис із `botLevel: 'casual'`, `points.counted: false`,
   лідерборд не змінився.
3. PvP-матч двома профілями: хід не в свою чергу через DevTools
   (`updateDoc` з `log.moves` +1) → `permission-denied`; нормальні ходи,
   ротація, здача, мат — проходять.
4. Quick match спарюється; `presence` лічильник видно.
5. Фідбек надсилається; текст > 1000 символів обрізається клієнтом (rules
   його б відхилили).
