# Subutai — промт-специфікація: аудіо-візуал, музика та стрім

> Скоуп: підсистема музики/біт-синку, стріму та аудіо-візуалу гри Subutai
> (Auxetic Chess960, React 19 + TypeScript + Vite). Ядро рушія шахів описане
> лише настільки, наскільки його торкається ця підсистема.
> Spotify і Twitch навмисно винесені окремими блоками; «Поліш» виділено в кінці.

---

## БЛОК 0 — Основа (board shell + аудіо-візуал)

Збери ігрову оболонку, де дошка живе у власному `.board-with-coords`
контейнері (точно по розміру дошки) і реагує на музичний біт навіть коли
музична панель закрита/згорнута.

- **Біт-рушій (`beatEngine`)** — єдине джерело правди про темп/фазу, живе поза
  React. Дві часові бази: `wall` (performance.now — для зовнішнього звуку/міка)
  і `track` (трек-клок Spotify). API: `setGrid(bpm, phaseMs)`, `adoptBpm`,
  `tap()` (tap-tempo), `msToNextBeat()`, `getIntervalMs()`, `onBeat()`,
  `scoreNow()`. Подвійний таймер (rAF + setInterval 250 мс) — щоб біти жили й у
  фонових вкладках, де rAF замерзає.
- **Пульс дошки в біт** — на кожен `onBeat` додавай клас `.beat-tick` на
  `.board-with-coords` (scale + brightness flash ~240 мс). Живе на рівні App,
  не в панелі, щоб працювало й при закритій музиці.
- **Аудіо-SFX** — короткі Web Audio войси, синтезовані на льоту (без семплів):
  хід, **взяття**, шах, мат, рулетка. Кожен «fire-and-forget».
- **Звукова естетика взяття**: тепле «взяв і поставив» — рожевий шум через
  м'який low-pass (~900 Гц, без резонансного свисту) + 2 дерев'яні синусні
  партіали (~190/285 Гц) + м'яка атака 4 мс. НЕ білий шум через вузький
  band-pass (читається як різке шипіння).

## БЛОК A — Spotify / музика + біт-синк *(окремий, опційний модуль)*

Мета: дошка рухається «в такт» будь-якій музиці без жодного API-ключа, OAuth
чи DRM. Працює з будь-яким джерелом звуку.

### Джерела звуку та визначення BPM
- **Live-захоплення** (`getDisplayMedia` для звуку вкладки / `getUserMedia` для
  міка) → FFT-аналізатор (`AnalyserNode`, 60 смуг, ~30fps). Live-захоплення
  **володіє** біт-сіткою (wall-база, завжди йде) — завантаження Spotify-embed
  не має скидати чи перебивати її темп.
- **Live-BPM (`liveBpm`)** — детектує kick/onset зі смуг басу (енергетичний
  flux над адаптивним порогом), будує гістограму інтер-онсетних інтервалів,
  октавно-згортає в музичний діапазон (70–200 BPM, покриває хардстайл).
  **Важливо:** використовуй ЛИШЕ консекутивні інтервали; октаво-стійкий вибір
  (half / detected / double) з легкою перевагою смузі 120–175.
- **Офлайн-аналіз файлу (`fileBpm`)** — для локального файлу маємо сирий сигнал:
  low-pass → енергетична огинаюча → onset-детекція → гістограма інтервалів →
  октавне згортання → циркулярно-середня **фаза** (де стоїть біт 1). Сітка
  семпл-точна з першого біта, без тапів. (Той самий принцип консекутивних
  інтервалів — щоб швидкі жанри не читались як half-time.)
- **Tap-tempo / пресети** — ручний фолбек (4+ тапи задають BPM, 1 тап
  ре-якорить фазу коли BPM уже відомий).
- **Per-track BPM-памʼять** + збережені проаналізовані плейлисти.

### Beat Mode (хід у біт)
Опційний режим (класична соло-гра): людський хід «прилипає» до біта — його
коміт затримується так, щоб **пішак доїхав на біт**. Стан гри НЕ змінюється,
тільки тайминг візуального коміту.
- `snapPlan(slideMs)` повертає `{ holdMs, landMs }`: для ходу зі слайдом
  (260 мс) комітимо `slideMs` РАНІШЕ, щоб гліз **закінчився** рівно на біт
  (не починався — інакше пішак приїжджає на довжину слайда пізніше й «лагає»).
- Візуальний фідбек: на цільовій клітинці conic-ring «countdown», що
  заповнюється рівно за час очікування й «попає» на біт.

### Музична панель (dock)
- Згортається в компактний бар (аудіо + сітка + пульс дошки продовжують йти),
  пін у **низ-зліва**.
- Док у **ліву колону** на повну висоту (стрім-лейаут: Spotify зліва).
- Вільне перетягування з персистом позиції. **Розгортання з мінімізованого
  стану не має йти за нижній край екрана** — клампити верх по реальній висоті
  панелі + підтягувати назад у видиму зону.

## БЛОК B — Twitch / стрім-інтеграція *(окремий, опційний модуль)*

Мета: глядачі стріму взаємодіють із грою через чат, без OAuth/секретів.

- **Чат (`chat.ts`)** — анонімний read-only IRC (`justinfan<digits>`, без
  токена). Capability `twitch.tv/tags` → `display-name` + `color`, щоб ніки
  виглядали як у реальному чаті. Статуси: idle/connecting/connected/error.
- **Прогноз результату (`predictions.ts`)** — глядачі пишуть
  `!white/!black/!draw` (`!w/!b/!d`) поки йде гра; рахується останній голос
  кожного ніка (можна передумати). На кінці гри ті, хто вгадав, — переможці.
- **Голосування за хід (`moveVoting.ts`)** — один пайплайн, два режими:
  - `predict` — рушій обирає хід; хід + 3 декої як `!1..!4`, вікно 15 с, тоді
    реал розкривається (hold 3.5 с) і грається. Вгадав = +1.
  - `chat` — «чат проти стрімера»: 4 легальні ходи, топ-голосований СТАЄ ходом
    ШІ (нічия→рандом, 0 голосів→рандом). Переможці +1.
  - Скоринг матчу → лідерборд у кінці (+1 за хід, +3 за результат).
- **Емоути 7TV (`seventv.ts`)** — підтягувати емоути підключеного каналу.
- **Стрім-лейаут** — Twitch-чат докається у **праву** колону (Spotify — ліва).

## ПОЛІШ *(виділено окремо — дрібні, але важливі доведення)*

1. **Еквалайзер по периметру — «за дошкою»**: тонкі **сірі** палички (28/сторону,
   gap 2px), `z-index` ПОЗАДУ дошки — виглядають з-під країв. Кожна сторона
   читає енергійну смугу за позицією (гучний бас посередині, затухання до
   кутів) — усі 4 сторони живі. Маски на кінцях сторін + м'який сірий бас-halo
   → **без гострих кутових «Г»**. (Колір — placeholder-сірий; далі —
   звуко-реактивна фонова сітка на задньому плані.)
2. **Згладжування хвилі**: 5-tap просторовий блюр + темпоральний ease (0.5) +
   нижче analyser-smoothing (0.6) — тече як одна хвиля, мінімум лагу.
3. **Beat-snap «приземлення на біт»** замість «старт слайда на біт».
4. **Пульс дошки** глибший (scale 1.04), щоб «тап» у біт був відчутний.
5. **Звук взяття** теплий і м'який (див. Блок 0).
6. **Перф чату**: рядки чату мемоїзовані (`React.memo`) — жвавий канал
   (50+ msg/s) більше не морозить скоринг. Емісія лічильників голосів
   коалесцена (~7×/с).
7. **Авто-синк надійність**: live-захоплення володіє сіткою; трек-сітки
   стартують на реальному playback_update (без гонки зі збереженим URL).
8. **Док**: мінімізація в низ-зліва; коректне розгортання у видиму зону.

## Інваріанти / обмеження
- Жодних API-ключів, OAuth, секретів, DRM. Усе — публічні веб-API.
- Музика/Twitch — **опційні** модулі; ядро гри працює без них.
- Beat Mode не змінює стан гри — лише тайминг візуального коміту.
- Перф: per-frame вартість аудіо-візуалу — лише запис CSS-змінних
  (transform/opacity, compositor-only); жодних per-bar box-shadow щокадру.
