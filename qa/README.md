# Регресійні тести рушія Subutai

Скрипти не залежать від гілки, на якій лежать: код застосунку вони беруть з
`QA_SRC` (за замовчуванням — `src/` цього ж checkout-а). Тож будь-яку гілку
можна перевірити, не переносячи на неї ці файли.

## Запуск (tsx, без встановлення пакетів)

```bash
npx tsx qa/engine/fuzz-invariants.ts     # FUZZ_GAMES=2000 FUZZ_PLIES=160 FUZZ_SEED=1
npx tsx qa/engine/replay-roundtrip.ts    # RT_GAMES=400
npx tsx qa/engine/bot-rotation-guard.ts  # BOT_GAMES=60
npx tsx qa/engine/roulette-log.ts        # ROU_GAMES=300  (очікувано падає, див. нижче)

# інший checkout:
QA_SRC=C:/projects/other/src npx tsx qa/engine/fuzz-invariants.ts
```

| Скрипт | Що перевіряє |
|---|---|
| `fuzz-invariants.ts` | Тисячі випадкових легальних партій з ротаціями. Незалежний оракул (`oracle.ts`) грає звичайні шахи на ВІЗУАЛЬНІЙ сітці 8×8, виміряній з DOM (`fixtures/visual-layout.json`), і порівнює з рушієм кожен хід: пішак не стоїть на візуально крайньому ряду, легальні ходи не лишають короля під боєм, ротація двічі поспіль заборонена, en passant — лише одразу після подвійного ходу в A і B, мат/пат, облік рокіровок. Репро кожного порушення — у `qa/out/` у форматі «Load replay». |
| `replay-roundtrip.ts` | Нотація «Copy to clipboard» → «Load replay» дає ту саму позицію; експортер застосунку пише той самий формат, що й незалежний writer (`play.ts`). `QA_WRITE_REPLAYS=1` перегенеровує `fixtures/replays.json`. |
| `bot-rotation-guard.ts` | Пошук бота (з TT на всю партію, як у застосунку) ніколи не пропонує другу ротацію поспіль, не повертає null і нелегальний хід. |
| `roulette-log.ts` | Логи Roulette (дві дії за хід): чи правильно реплей логу визначає, хто ходив, і чи `computeGamePoints` зараховує людині саме її взяття. |
| `find-endings.ts` | Генерує `fixtures/endings.json` — легальні партії за хід до мату в A і в B (для ручних перевірок фінальних сцен). |

Самоперевірка оракула: п'ять навмисно зламаних копій рушія (промоушен за міткою
ряду, без промоушену при ротації, EP після ротації, жертва EP за арифметикою
міток, прапорець ротації) — фазер ловить усі п'ять.

## Очікуване падіння

`roulette-log.ts` **очікувано падає** до виправлення QA-08 (заплановано на
v1.1): лог Roulette не зберігає, хто зробив хід, тож реплей приписує кожну
другу дію не тій стороні, а очки за взяття в Roulette рахуються неправильно.
Це відома вада, а не регресія. Коли QA-08 виправлено, скрипт має проходити, і
цей розділ треба прибрати.

Решта скриптів (`fuzz-invariants`, `replay-roundtrip`, `bot-rotation-guard`)
мають проходити на кожному коміті.

`qa/out/` (репро-логи) у git не йде.
